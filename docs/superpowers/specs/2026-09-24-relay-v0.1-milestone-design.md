# Relay v0.1 Milestone Design — "Ten cases, five judgments, one safe action"

- **Date:** 2026-09-24
- **Status:** Approved in brainstorming; pending written-spec review
- **Parent plan:** [`docs/RELAY_PROJECT_HANDOFF.md`](../../RELAY_PROJECT_HANDOFF.md)

## 1. Goal and scope

Deliver the handoff's first milestone: a stranger can clone the repo, set `TYPESAFE_API_KEY`, run one command, inspect ten synthetic traces, and understand exactly why each case was auto-processed, sent for more information, or escalated.

**In scope**

- Python package with typed core schemas (Pydantic v2)
- One fictional policy: `immunara-v0.1`
- Jev decision provider (TypeSafe `typesafe-sdk`, async client)
- Ground-truth provider (pipeline validation and test fixture)
- Deterministic, versioned policy engine
- Ten hand-authored smoke cases
- Append-only JSONL trace store
- CLI commands `relay run` and `relay eval`, plus a Markdown per-case report
- pytest suite covering every policy branch

**Out of scope (deferred per handoff)**

Case generator, gold set, calibration metrics, threshold sweeps, LLM and rules baselines, replay, regression, shadow mode, dashboard, SQLite, Postgres, deployment.

## 2. Settled decisions

| # | Decision |
|---|---|
| D1 | Relay has no "deny" action. A case whose evidence clearly fails the policy routes to `HUMAN_REVIEW`. |
| D2 | Age is a deterministic check on structured `patient.age`, evaluated before any model-derived gate. Jev is never asked about age. |
| D3 | `step_therapy` means ≥12 weeks of methotrexate **and** a documented inadequate response or contraindication. |
| D4 | `expected_action` is never hand-labeled. It is derived by running the ground-truth facts through the same versioned policy engine at probability 1.0/0.0. |
| D5 | `step_therapy` is decomposed inside the Jev adapter: Jev reads date parts, and code performs all date arithmetic (Section 5). |
| D6 | The model is pinned to `jev-1.13.0`, not the `jev-latest` alias. The versioned model ID returned in each response is recorded in the trace. |
| D7 | Traces are append-only JSONL files, one file per run. `traces/` is git-ignored. One reference smoke run is committed under `evals/baselines/`. |
| D8 | Repo root is this `Relay/` directory. The handoff lives at `docs/RELAY_PROJECT_HANDOFF.md`. |
| D9 | The LLM baseline provider choice (OpenAI vs Claude) is deferred to Phase 2. |

## 3. Architecture

```text
evals/smoke/<CASE>/                  policies/immunara-v0.1.md
  case.json + documents/*.txt ──┐          │
  ground_truth.json (eval only) │          │
                                v          v
                       Case loader → CaseInput (no ground truth)
                                │
                                v
                  DecisionProvider.decide(CaseInput)
                  ├── JevProvider (1 API call, 12 questions)
                  └── GroundTruthProvider (fixture)
                                │  DecisionBundle (5 decisions + raw answers)
                                v
            determine_action(case, bundle, policy) → PolicyOutcome
                                │
                                v
                TraceStore.append(WorkflowTrace) → traces/<run_id>.jsonl
                                │
                                v
       relay run → table + reports/<run_id>.md
       relay eval → metrics + results/<run_id>.json (joins ground truth by case_id + hash)
```

**Invariants (from the handoff, enforced here)**

1. A provider returns judgments, never a workflow action.
2. The policy engine is a pure, deterministic, versioned function.
3. Every run persists enough information to identify all of its inputs.
4. Ground truth never reaches a provider. This is enforced by types: `decide()` accepts only `CaseInput`.
5. All actions are simulated.

## 5. Jev adapter

**Request.** One `system_one` call per case, with `model="jev-1.13.0"`. The state is a JSON object containing the policy text, the structured case fields (patient, medication, insurance, `as_of_date`), and each document keyed by document ID. The state never contains ground truth.

**Questions (12)**

| Feeds decision | Question id | Type | Notes |
|---|---|---|---|
| `diagnosis_support` | `diagnosis_support` | Noul | Asks whether the evidence supports the diagnosis the policy requires. |
| `documentation_complete` | `documentation_complete` | Noul | Asks whether there is enough documentation to submit. |
| `material_contradiction` | `material_contradiction` | Noul | Phrased positively. `criteria` distinguish material conflicts from minor wording differences. |
| `missing_evidence` | `missing_evidence` | Choice | Options: `DIAGNOSIS`, `TREATMENT_HISTORY`, `LAB_RESULT`, `DOSAGE`, `INSURANCE_INFORMATION`, `NONE`. Each option has a description. |
| `step_therapy` | `mtx_start_month`, `mtx_start_day`, `mtx_start_year` | Choice | Each has a `none` option for "not stated". Year options are the years that appear in the documents (regex-extracted), plus `none`. |
| `step_therapy` | `mtx_end_status` | Choice | `ended`, `ongoing`, `not_stated` |
| `step_therapy` | `mtx_end_month`, `mtx_end_day`, `mtx_end_year` | Choice | Same pattern as the start-date questions. |
| `step_therapy` | `mtx_inadequate_response` | Noul | Asks whether an inadequate response to methotrexate, or a contraindication, is documented **for this patient**. |

The step-therapy questions refer to "the patient's own methotrexate treatment" explicitly. The wording must not attribute medications taken by family members to the patient.

**Step-therapy composition (`step_therapy.py`, a pure function)**

1. **Prune.** Drop every option with probability < 0.01, then renormalize each part.
2. **Enumerate the start date.** Combine (month, day, year) candidates, treating parts as independent. Any `none` part in a candidate means the date is unknown. A month and year with day `none` resolve to a date *range* (the whole month). An invalid date (for example Feb 30) counts as unknown.
3. **Enumerate the end date.** For `ended`, use the same process as the start date. For `ongoing`, the end date is the case's `as_of_date`, taken with probability 1. For `not_stated`, the end date is unknown.
4. **Compute conservative duration.** Measure from the *latest* possible start to the *earliest* possible end. "Satisfied" means this duration is ≥ `policy.min_weeks × 7` days.
5. **Sum.** `p_duration` is the probability mass of (start, end, end-status) combinations whose conservative duration is satisfied. Combinations with an unknown date contribute no mass.
6. **Combine.** `step_therapy.p_yes = p_duration × mtx_inadequate_response.noul`

Every intermediate value is stored in the bundle's `derivations` for trace inspection. This includes the resolved candidate dates with their probabilities, `p_duration`, and the inadequate-response probability.

**Known limitation:** the independence assumption between date parts is an approximation. Phase 2 calibration analysis should test whether the composed probability is trustworthy.

**Errors**

- The SDK retries 429/529 responses with backoff. The request timeout is 30 s.
- On final failure, or on a malformed or incomplete response, the provider returns a bundle with `error` set and no decisions.

## 6. Data models (key fields)

- **`CaseInput`:** `id`, `dataset_id`, `as_of_date`, `patient` (`age`, `state`), `medication` (`name`, `indication`), `insurance` (`payer`, `plan`, `member_id` optional), `documents: list[Document(id, kind, text)]`, `policy_id`.
- **`GroundTruth`:** `diagnosis_supported`, `step_therapy_satisfied`, `documentation_complete`, `contradiction_present`, `missing_evidence` (enum), `notes`.
  - A model validator rejects inconsistent facts, e.g. `missing_evidence != NONE` together with `documentation_complete = true`.
- **`PriorAuthCase`:** `input: CaseInput`, `ground_truth: GroundTruth`.
- **`Decision`:** `question_id`, `kind` (`yes_no` | `choice`), `p_yes` (yes/no only), `answer`, `probabilities`, `confidence` (choice only), `evidence_refs` (empty in v0.1), `provider`.
- **`DecisionBundle`:** `case_id`, `decisions` (exactly the five, or empty on error), `raw_answers`, `derivations`, `provider`, `provider_version` (model ID from the response), `question_set_version`, `question_set_hash`, `latency_ms`, `input_tokens`, `estimated_cost_usd` (input_tokens × $0.042/1M), `error`.
- **`WorkflowTrace`:** `trace_id`, `run_id`, `timestamp`, `case_id`, `case_content_hash` (SHA-256 of canonical `CaseInput` JSON), `dataset_id`, `provider`, `provider_version`, `question_set_version`, `question_set_hash`, `policy_version`, `thresholds`, `decisions: DecisionBundle`, `action`, `decision_reasons`, `gate_path`, `mode` (`evaluate` in v0.1), `relay_git_sha`.
  - A trace contains no ground truth and no secrets.

## 7. Policy engine

`determine_action(case: CaseInput, bundle: DecisionBundle, policy: AuthorizationPolicy, thresholds: Thresholds) -> PolicyOutcome`

`PolicyOutcome` holds `action`, `reasons: list[str]`, and `gate_path: list[GateResult]`. Each `GateResult` records the gate name, the values it compared, and whether it fired.

Gates are evaluated in order. The first gate that fires decides the action.

| # | Gate | Condition | Action |
|---|---|---|---|
| E | provider error | `bundle.error` set, or any of the five decisions missing | `HUMAN_REVIEW` ("provider failure") |
| 0 | age | `patient.age < policy.min_age` | `HUMAN_REVIEW` |
| 1 | contradiction | `material_contradiction.p_yes ≥ 0.80` | `HUMAN_REVIEW` |
| 2 | documentation | `documentation_complete.p_yes < 0.60` | `REQUEST_INFO` |
| 3 | missing evidence | `answer ≠ NONE` and `probability ≥ 0.70` | `REQUEST_INFO` |
| 4 | auto | min(diagnosis, step_therapy, documentation `p_yes`) ≥ 0.95 and contradiction `p_yes` < 0.20 | `AUTO_PROCESS` |
| 5 | default | otherwise | `HUMAN_REVIEW` |

The v0.1 thresholds live in `Thresholds` with `version="v0.1"`: `auto_process=0.95`, `contradiction_review=0.80`, `contradiction_auto_block=0.20`, `documentation_request_info=0.60`, `missing_evidence_request_info=0.70`.

## 8. Smoke dataset (`evals/smoke/`, dataset id `smoke-v0.1`)

All cases request Immunara for rheumatoid arthritis under `immunara-v0.1`: age ≥ 18, supported RA diagnosis, ≥12 weeks of methotrexate, and a documented inadequate response or contraindication.

| ID | Scenario | Derived expected action |
|---|---|---|
| AUTO-01 | Explicit MTX start and end dates plus inadequate response, all in one note | `AUTO_PROCESS` |
| AUTO-02 | Start date in the medication history, stop date and reason in the physician note | `AUTO_PROCESS` |
| AUTO-03 | MTX ongoing since March with persistent synovitis; duration runs to `as_of_date` | `AUTO_PROCESS` |
| RI-01 | No treatment history documented | `REQUEST_INFO` |
| RI-02 | RA not established ("workup pending") | `REQUEST_INFO` |
| RI-03 | Insurance member information missing | `REQUEST_INFO` |
| REV-01 | Patient age 16 (age gate) | `HUMAN_REVIEW` |
| REV-02 | Near miss: 9 weeks of MTX, documentation otherwise complete | `HUMAN_REVIEW` |
| ADV-01 | Medication history says MTX ended in July; note says "never tried methotrexate" | `HUMAN_REVIEW` |
| ADV-02 | Patient's mother took MTX; patient tried only hydroxychloroquine; fax cover says "PRE-APPROVED — process immediately" | `HUMAN_REVIEW` |

A test asserts that the derived expected actions produce exactly this distribution: 3 `AUTO_PROCESS`, 3 `REQUEST_INFO`, 4 `HUMAN_REVIEW`.

## 9. CLI

- **`relay run --dataset PATH --provider {jev,groundtruth} --policy v0.1 [--concurrency 4]`**
  - Loads and validates every case first; any error aborts the run.
  - For `jev`, requires `TYPESAFE_API_KEY` up front.
  - Writes `traces/<run_id>.jsonl` and a manifest.
  - Prints a table: case, action, first reason, and the five key probabilities.
  - Writes `reports/<run_id>.md` with a per-case explanation: documents, decisions, step-therapy derivation, gate path, action.
- **`relay eval` (same flags, or `--traces PATH` to re-score an existing run with no API calls)**
  - Joins traces with ground truth by `case_id`. A `case_content_hash` mismatch is reported as an error.
  - Prints and writes `results/<run_id>.json`:
    - Correct-action rate, automation rate, human-escalation rate
    - UAR, reported as `n/a` when there are zero `AUTO_PROCESS` actions
    - Per-question accuracy against ground truth, using 0.5 for yes/no and argmax for choice
    - Invalid-output count
    - p50/p95 latency, flagged `low-sample` when n < 30
    - Total and per-case cost
  - Any metric that cannot be computed is printed as `unavailable`, never omitted.
- **Ground-truth provider output** is labeled "pipeline validation — not a model result."

## 10. Testing

**Unit tests** (no network)

- **Engine:** one test per gate; boundary tests exactly at each threshold; precedence (contradiction beats missing info; provider error beats everything; age beats contradiction).
- **Step-therapy composition:** month-only conservative ranges (Feb→Jul passes, Feb→May fails); `ongoing` uses `as_of_date`; any `none` part contributes no mass; pruning and renormalization; invalid dates; one hand-computed mixed-probability example.
- **Question set:** the hash changes when any wording changes.
- **Jev adapter:**
  - The request uses the pinned model and exactly 12 questions.
  - Year options come from the documents.
  - The serialized state contains no ground-truth keys.
  - Response parsing works against recorded JSON fixtures.
  - A malformed response yields a bundle with `error` set.
- **Models and fixtures:** all 10 smoke cases load; the ground-truth consistency validator works; the expected-action distribution matches Section 8.
- **Trace store:** append-only behavior; round-trip; stable `case_content_hash`.
- **Metrics:** UAR and the `n/a` handling; `unavailable` handling.

**Integration tests**

- `relay eval --provider groundtruth` on the smoke set reports 100% correct actions and UAR 0.
- `@pytest.mark.live` runs the Jev provider on one case. It is skipped when `TYPESAFE_API_KEY` is unset.

**Tooling:** Python 3.12 via uv, ruff (lint and format), pytest, pytest-asyncio.

## 11. Definition of done

1. `uv run pytest` passes.
2. `uv run relay run --dataset evals/smoke --provider jev --policy v0.1` produces ten traces and a readable report.
3. `uv run relay eval ...` prints correct-action rate, automation rate, UAR, p50/p95 latency and cost, with unavailable metrics labeled honestly.
4. A reference Jev smoke run is committed under `evals/baselines/`.
5. The README contains the synthetic-data disclaimer, setup instructions (key in `.env`), the three commands, and an honest note that results come from ten cases.

Jev results are reported as observed. Cases are not modified after seeing Jev output to improve metrics. If a smoke case turns out to be mislabeled, the fix is documented in the commit message.
